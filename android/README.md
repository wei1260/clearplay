# 澄映播放器 · Android

成品：`../release/Clearplay-0.1.10-android.apk`。最低 Android 8.0（API 26），无需连接电脑或运行外部服务。已安装到 REDMI K80，百度和夸克的实际按钮下载及文件校验通过。

## 下载视频

- 在百度或夸克的视频列表中，直接点击视频右侧“下载”，无需先播放。
- 播放控制条也有“下载”，用于保存当前选中的网盘视频。
- 原文件保存到手机 **下载/澄映** 目录，文件名加时间后缀以避免覆盖已有文件。
- 进度行显示最新任务的状态、进度和速度；点击进度行打开系统下载记录。任务交给系统下载管理，应用退到后台后仍可继续。
- 下载只取原文件，不等待视频转码或播放准备，也不把低画质视频当成原文件。百度沿用新链路，不回退普通原文件下载。
- Android 8/9 首次保存需要系统存储权限；Android 10 及以上无需此权限。

## 使用

1. 将 APK 传到手机后安装。本机连接的 REDMI K80 已安装正式版。
2. 选择“百度网盘”或“夸克网盘”，点“登录”。在官网页面完成登录后，点击“完成登录”；实际验证目录成功才保存已连接状态。
3. 浏览文件夹并选择视频。可用画质先起播，其他画质在后台补充；在“画质 → 刷新可用画质”中可重新查询，不中断当前播放。支持原文件、实际可用的转码及 2K、0.5～4 倍速、暂停、前后跳转、全屏和下一集。
4. “打开本地”使用系统文件选择器，可多选；播放记录在手机本机保存。“账号”中可设置自动播放下一集或断开对应网盘。

手机端需要单独登录；不会复制电脑端的网盘账号会话。不需要填写百度应用 AppKey / SecretKey。登录页面没有注入本机 JavaScript 接口，密码和验证码只在官网输入；媒体凭据、签名地址不显示在界面或日志中。

使用 AndroidX Media3 原生播放内核，支持哪些视频编码仍取决于手机解码能力、源文件、网盘转码与账号权益。百度视频准备响应按平台返回的时间等待，独立音频可用时与画面一同播放。

百度使用官方手机登录入口；夸克保留可实际登录的官方端点并适配手机宽度，默认显示手机短信登录，不会自动提交表单或同意协议。手机代理直接打开夸克首页会被其网站导向客户端下载页，所以夸克沿用官网支持的浏览器标识，仅调整登录框布局。

2K 不会通过放大画面生成，也不会突破账号权限。夸克按返回的真实分辨率标识；百度的 2K 请求可能降级返回 720P，后台会读取首个视频分片的格式来确认分辨率并去重。未完成转码的文件可稍后刷新；权限不足需要账号实际获得对应权益。

### v0.1.7 原画读取改进（2026-11-10）

- 夸克下载接口使用客户端请求头，并在取得直链后读取更新后的登录状态。相同两个真实文件，网页取链均返回 23018；客户端取链均成功。
- 同账号、同网络对两个文件分别交错测试整文件、单路固定分段、三路固定分段，两轮共 12 个完整样本，每个样本 16 或 32 MiB。全部 SHA-256 对照一致；首轮整文件作为各自基准。单路整文件约 3.44～9.28 MB/s，三路分段约 5.39～10.53 MB/s；同文件同轮提升约 13%～57%。数字为本机样本，不代表所有账号或持续满速承诺。
- 安卓夸克原画采用 4 MiB 分段、最多三路预读取，按文件顺序交给播放器；跳转/停止时取消旧读取。核对 HTTP 206、Content-Range、文件大小和分段完整性；服务端忽略 Range 时退回原有单路读取。转码流保持原有读取方式。
- 百度比较了 filemetas、客户端请求头、PCS file/stream 和带本机登录签名的 locate 路径。原有路径约 33～76 KB/s；locate 三路约 117 KB/s，但第二个文件出现 403，限定时间内未完成完整样本校验。未将这些实验路径接入正式版，也不标为解除百度限速。
- 18 项单元测试通过，包含乱序完成后的拼接、末段、跳转读取边界、服务端忽略 Range、错误分段/截断、取消及下载请求头与新会话。详细测速 JSON 位于 `../test-results/android/throughput/`，`passed=false` 的两次初始诊断因息屏/中断作废。
- REDMI K80 上两条 1920×1080 原画均通过连续 60 秒的 2 倍速检查，进度分别推进 119.86 / 119.93 秒，观察到的再缓冲为 0，音视频均正常；起播约 4.63 / 2.82 秒，跳转到 2 分钟后均恢复。百度 720P 回归：起播约 20.93 秒，15.08 秒内推进 29.68 秒，再缓冲为 0。这些是有限样本验收，非所有文件保证。
- 本次接入的是在线播放取链与预读取；尚无离线下载任务列表或“保存到手机”功能。Windows 成品仍为 0.1.3。

真实播放及最终包验证见 `../test-results/android/package-report-0.1.7-android.json`。

## 重新构建

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1
```

工具默认位于 `D:\agent\android-build-tools`，可通过 `-ToolsRoot` 指定其他位置。需要完整 JDK 21、Gradle 8.13、Android SDK Platform 35 和 Build Tools 35.0.0；本机已准备好这些工具。脚本将源码复制到工具目录下的 ASCII 工作目录，避开 Windows 中文路径下 JVM 测试类加载问题，然后构建、测试、运行 Lint 并验证签名。

正式版签名密钥保存在工具目录的 `signing/`，口令通过 Windows 当前用户的 DPAPI 保护，不进入源码或 APK。后续升级沿用该密钥和应用 ID；请保留该目录以继续签名更新。

设备测试构建：

```powershell
node scripts/create-android-fixture.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Configuration Debug -BuildDeviceTests
```

仅更新诊断组件、保留正式安装包：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Configuration Release -DiagnosticsOnly`。
诊断 APK 安装后可运行 `node scripts/test-android-throughput.cjs --provider=quark --mib=16 --segment=4 --seconds=25 --rounds=2`；百度使用 `--provider=baidu`，额外 locate 路径用 `--route=locate`。一次只运行一个测速进程。诊断会打开播放器并临时保持常亮，不导出 Cookie、签名地址或媒体内容；结束后关闭常亮。

百度追加实验可选 `--route=explore`（网页签名取链和最多三个返回节点），或 `--route=web-signed`；`--workers=8` 可把并发对照上限从三路改为八路。实际未测出稳定提速，未接入正式版；结果见 `../test-results/android/throughput/BAIDU-EXPERIMENT-2026-11-10.md`。诊断的 `passed` 只代表用例完成，不代表下载成功或提速。

测试版应用 ID 带 `.debug`，与正式版隔离。测试视频只打入设备测试 APK。

明确需要检查本机已登录夸克账号时，构建同一发布签名的设备测试 APK，再运行 `node scripts/test-android-quark.cjs --play`。该检查会在手机内读取有限目录并播放一条视频；必须显式启用账号检查，普通测试不会自动读取真实账号。结果只包含状态码、字段结构、媒体格式和解码计数，不保存 Cookie 值或签名播放地址。发布签名的账号检查不运行会清空测试数据的 `PlaybackTest`。

播放器依赖及接入方式参考 [Media3 入门](https://developer.android.com/media/media3/exoplayer/hello-world)和 [HLS 支持](https://developer.android.com/media/media3/exoplayer/hls)。
